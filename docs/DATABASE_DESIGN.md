# DATABASE DESIGN
## MongoDB Collections — Version 1

---

## Overview

Four collections.

| Collection | Purpose |
|------------|---------|
| `orders` | The central operational entity. Every order from first contact to closure. |
| `declarations` | The formal business record. Maps to the Google Sheets Declaration spreadsheet. |
| `tasks` | Operator action items. Generated by the scheduler or created manually. |
| `lab_comm_threads` | Gmail thread monitoring records for laboratory communication. Independent lifecycle — queried by status and timeout across all orders. Added Phase L1. |

The design rule: if a piece of data has no meaning outside of a single order, it is embedded inside that order document. Separate collections exist only when the data has its own access pattern or must be queried independently.

---

## Collection: `orders`

The single source of truth for all operational data.

### Top-Level Fields

| Field | Type | Purpose |
|-------|------|---------|
| `_id` | ObjectId | System identifier |
| `status` | String | Current lifecycle status. One of: `NEW`, `WAITING_PAYMENT`, `IN_LAB`, `WAITING_CLIENT_APPROVAL`, `WAITING_ORIGINAL`, `READY_FOR_DELIVERY`, `COMPLETED`, `CANCELLED` |
| `balance_due` | Number | Maintained field: `pricing.amount` minus sum of all payment amounts. Must equal zero before completion is permitted. |
| `declaration_id` | ObjectId | Reference to the linked Declaration record |
| `created_at` | Date | When the order was first created |
| `updated_at` | Date | When the order was last modified |
| `cancelled_reason` | String | Populated only when status is `CANCELLED` |

---

### Embedded Object: `client`

Information about the person requesting the certification. Captured at intake, never split into a separate collection.

| Field | Type | Purpose |
|-------|------|---------|
| `name` | String | Full name |
| `phone` | String | Primary contact number |
| `contact_channel` | String | How they first made contact: `whatsapp`, `telegram`, `instagram`, `facebook`, `google_form`, `phone`, `other` |
| `notes` | String | Free-text operator notes about the client |
| `email` | String | Client email address. Used for order search. Optional. |
| `companyName` | String | Company name for B2B clients. Used for order search. Optional. |

---

### Embedded Object: `laboratory`

The external laboratory handling this order's certification work. Captured when the operator first contacts a lab, never split into a separate collection.

| Field | Type | Purpose |
|-------|------|---------|
| `laboratoryName` | String | Full name of the laboratory |
| `laboratoryEmail` | String | Email address used for requests and reminders |
| `laboratoryContact` | String | Contact person name at the laboratory |
| `expectedLayoutDays` | Number | SLA target: days expected to receive a layout. Snapshotted into `lab_comm_threads.sla_layout_days` at thread link time. Optional. |
| `expectedOriginalDays` | Number | SLA target: days expected to receive the original document. Snapshotted into `lab_comm_threads.sla_original_days` at thread link time. Optional. |

---

### Embedded Object: `pricing`

Pricing information for this order. Embedded data group — not a separate entity or collection.

| Field | Type | Purpose |
|-------|------|---------|
| `amount` | Number | Total quoted price |
| `calculated_at` | Date | When the quote was calculated |
| `communicated_at` | Date | When the quote was communicated to the client |

---

### Embedded Object: `deadlines`

Concrete date fields that drive all automated attention alerts. These are the most important operational fields after `status`. They must be set explicitly by the operator — the system does not calculate them automatically.

| Field | Type | Purpose |
|-------|------|---------|
| `lab_response_due` | Date | When the laboratory is expected to deliver a layout. Set when lab is contacted. |
| `client_response_due` | Date | When the client is expected to respond to a layout. Set when layout is sent to client. |
| `original_expected` | Date | When the original document is expected from the lab. Set when client approves layout. |

---

### Embedded Array: `payments`

All payments received for this order. Each payment is an independent entry. Payments are never deleted — they are voided with a note if recorded in error.

| Field | Type | Purpose |
|-------|------|---------|
| `date` | Date | Date payment was received |
| `amount` | Number | Amount received |
| `method` | String | `cash`, `transfer`, `card`, `other` |
| `note` | String | Optional operator note |
| `voided` | Boolean | True if this payment entry was recorded in error |
| `voided_at` | Date | When it was voided |
| `voided_reason` | String | Why it was voided |

`balance_due` on the top-level order is recalculated every time the payments array changes: `pricing.amount - sum(payments where voided = false)`.

---

### Embedded Array: `lab_interactions`

One entry per laboratory contact cycle. The first entry is version 1. Each correction loop that returns the order to `IN_LAB` adds a new entry with an incremented version.

| Field | Type | Purpose |
|-------|------|---------|
| `version` | Number | Iteration number. Starts at 1. |
| `sent_at` | Date | When the lab request was sent |
| `deadline` | Date | Expected layout delivery date for this iteration |
| `reminder_count` | Number | How many reminders have been sent in this iteration |
| `last_reminder_at` | Date | When the most recent reminder was sent |
| `layout_received_at` | Date | When the lab returned a layout for this iteration |
| `correction_notes` | String | Correction instructions sent to the lab for this iteration (empty on first iteration) |
| `gmail_thread_id` | String | Gmail thread ID linked by the Laboratory Communication Agent. Null until a thread is linked via Phase L1. |
| `gmail_linked_at` | Date | When the Gmail thread was linked to this `lab_interactions` entry. |

---

### Embedded Array: `layouts`

One entry per layout version received from the laboratory. Versions align with `lab_interactions`.

| Field | Type | Purpose |
|-------|------|---------|
| `version` | Number | Corresponds to the `lab_interactions` entry version |
| `file_ref` | String | File path or storage reference |
| `file_name` | String | Original filename |
| `received_at` | Date | When the layout file was recorded in the system |
| `sent_to_client_at` | Date | When the operator sent it to the client |
| `client_decision` | String | `approved` or `corrections_requested`. Null until client responds. |
| `correction_notes` | String | Client's correction instructions. Populated when decision is `corrections_requested`. |
| `decided_at` | Date | When the client communicated their decision |

---

### Embedded Object: `original`

Tracks the original printed document — from lab arrival to client delivery.

| Field | Type | Purpose |
|-------|------|---------|
| `received_at` | Date | When the original document arrived from the lab |
| `sent_to_client_at` | Date | When the operator sent it to the client |
| `delivery_method` | String | `post`, `courier`, `in_person`, `other` |
| `tracking_ref` | String | Courier tracking number or other delivery reference |

---

### Embedded Array: `events`

An append-only log of everything that has happened to this order. Never modified, never deleted.

| Field | Type | Purpose |
|-------|------|---------|
| `timestamp` | Date | When the event occurred |
| `type` | String | Event category (see event types below) |
| `description` | String | Human-readable description of what changed |
| `actor` | String | `operator` or `system` (scheduler-generated events use `system`) |

See `docs/WORKFLOW_EVENTS.md` for the authoritative event code catalog.

---

### Indexes on `orders`

| Index | Fields | Reason |
|-------|--------|--------|
| Primary | `_id` | Default |
| Status filter | `status` | Dashboard queries filter by status |
| Deadline scan | `deadlines.lab_response_due`, `deadlines.client_response_due`, `deadlines.original_expected` | Scheduler scans these daily |
| Declaration link | `declaration_id` | Sync lookups |
| Client search | `client.phone` | Operator searches by phone number |
| Client name search | `client.name` | Case-insensitive search (collation: en, strength 2) |
| Company name search | `client.companyName` | Case-insensitive search, sparse |
| Client email search | `client.email` | Prefix match, sparse |
| Lab name search | `laboratory.laboratoryName` | Lab lookup, sparse |
| Lab email search | `laboratory.laboratoryEmail` | Lab lookup, sparse |
| Created sort | `created_at` | Default sort for order lists |

## Collection: `declarations`

Represents the formal business record — the rows in the Google Sheets Declaration spreadsheet. This collection exists separately from `orders` because:

1. The spreadsheet has a fixed external structure that must be honored
2. Sync state (sheet row ID, last sync time, conflict flags) does not belong on the Order
3. The Declaration may be queried, exported, or reported on independently of Order workflow state

### Fields

| Field | Type | Purpose |
|-------|------|---------|
| `_id` | ObjectId | System identifier |
| `order_id` | ObjectId | Reference to the linked Order. May be null if a sheet row has not yet been matched to an Order. |
| `payment_date` | Date | From spreadsheet column: payment date |
| `payment_amount` | Number | From spreadsheet column: payment amount |
| `client_name` | String | From spreadsheet column: client |
| `document_type` | String | From spreadsheet column: document type |
| `phone` | String | From spreadsheet column: phone |
| `notes` | String | From spreadsheet column: notes |
| `status` | String | From spreadsheet column: status |
| `source` | String | `google_sheets` (auto-imported) or `manual` (created in system) |
| `sheet_row_id` | String | The row identifier in Google Sheets. Used to match updates and prevent duplicate imports. |
| `sync_status` | String | `synced`, `pending`, `conflict`, `error`, `row_deleted` — see note below |
| `conflict_details` | String | Description of sync conflict, if any |
| `last_synced_at` | Date | When this record was last successfully written to/from Sheets |
| `created_at` | Date | When this Declaration record was created in the system |

**`sync_status` values:**
- `synced` — declaration matches the sheet row and was last written by this system
- `pending` — a local change has not yet been written back to the sheet
- `conflict` — the sheet row was manually edited since the last system write; requires operator resolution
- `error` — the last sync attempt failed; will be retried on the next sync run
- `row_deleted` — the previously synchronized Google Sheets row no longer exists in the source sheet; the declaration is preserved for audit purposes and the operator is alerted

### Indexes on `declarations`

| Index | Fields | Reason |
|-------|--------|--------|
| Primary | `_id` | Default |
| Order link | `order_id` | Join with orders |
| Sheet lookup | `sheet_row_id` | Sync deduplication |
| Sync status | `sync_status` | Scheduler scans for pending/conflict |

## Collection: `tasks`

Operator action items. The bridge between automated detection (scheduler) and human execution (operator).

Tasks are never automatically completed. Only the operator can mark a task done, snooze it, or dismiss it.

### Fields

| Field | Type | Purpose |
|-------|------|---------|
| `_id` | ObjectId | System identifier |
| `order_id` | ObjectId | The order this task belongs to |
| `type` | String | Task category. One of: `remind_lab`, `follow_up_client`, `send_layout`, `send_original`, `check_payment`, `stale_intake`, `manual` |
| `description` | String | Human-readable description of what needs to be done |
| `priority` | String | `high`, `medium`, `low`. Determines dashboard display order. |
| `status` | String | `open`, `done`, `snoozed`, `dismissed` |
| `source` | String | `auto` (created by scheduler) or `manual` (created by operator) |
| `due_date` | Date | When this task should be acted on |
| `snoozed_until` | Date | Populated when status is `snoozed`. Task resurfaces on this date. |
| `created_at` | Date | When the task was created |
| `completed_at` | Date | When the task was marked done or dismissed |

### Deduplication Rule

Before creating a new auto-generated task, the system checks whether an `open` task of the same `type` already exists for the same `order_id`. If one exists, no duplicate is created. The existing task's `due_date` may be updated if the deadline has changed.

### Indexes on `tasks`

| Index | Fields | Reason |
|-------|--------|--------|
| Primary | `_id` | Default |
| Dashboard query | `status`, `due_date` | Dashboard loads all open/snoozed tasks sorted by due date |
| Order tasks | `order_id`, `status` | Order detail view shows its open tasks |
| Deduplication | `order_id`, `type`, `status` | Pre-insert duplicate check |

## Collection: `lab_comm_threads`

Gmail thread monitoring records for laboratory communication. Each record tracks one Gmail thread from the moment the operator links it until the lab replies or the thread is closed.

This collection exists separately from `orders.lab_interactions` because:
1. The poller (Phase L2) queries threads by `status` and `last_checked_at` across all orders — a cross-order pattern that cannot be expressed on an embedded array.
2. Thread lifecycle (`waiting` → `replied` → `closed`) is independent of order lifecycle.
3. Thread-level error tracking and poll state belongs to the monitoring record, not the order.

### Fields

| Field | Type | Purpose |
|-------|------|---------|
| `_id` | ObjectId | System identifier |
| `order_id` | ObjectId | Reference to the linked Order |
| `thread_id` | String | Gmail thread ID |
| `context` | String | `lab_interaction` or `lab_print_order` |
| `lab_interaction_version` | Number | 1-based version number. Set for `lab_interaction` context only. Null for `lab_print_order`. |
| `recipient_email` | String | Lab email address snapshotted at link time. Not updated if Order.laboratory changes. |
| `status` | String | `waiting`, `replied`, `timed_out`, `unreachable`, `closed`, `unlinked` |
| `link_mode` | String | `live` (linked when email was sent) or `historical` (linked retroactively) |
| `linked_at` | Date | When this record was created |
| `sent_at` | Date | When the operator sent the originating email. Null if unknown at link time. |
| `sla_layout_days` | Number | Snapshot of `laboratory.expectedLayoutDays` at link time |
| `sla_original_days` | Number | Snapshot of `laboratory.expectedOriginalDays` at link time |
| `initialized_message_count` | Number | Gmail message count at link time. Baseline for reply detection. |
| `last_checked_at` | Date | When the poller last checked this thread |
| `last_known_message_count` | Number | Message count as of last poll |
| `auto_reply_count` | Number | Auto-reply messages detected and excluded from reply count |
| `reply_detected_at` | Date | When a non-auto-reply was first detected |
| `reply_has_attachment` | Boolean | Whether the reply contained a PDF or image attachment |
| `reply_sender` | String | Email address of the reply sender |
| `timeout_at` | Date | Effective deadline: explicit operator deadline, or `sent_at + SLA`, or null |
| `error_count` | Number | Consecutive poll failures |
| `last_error_at` | Date | When the most recent poll error occurred |
| `last_error_message` | String | Error description from last failure |
| `created_at` | Date | When this record was created |

### Indexes on `lab_comm_threads`

| Index | Fields | Reason |
|-------|--------|--------|
| Primary | `_id` | Default |
| Poller scan | `status`, `last_checked_at` | Phase L2: fetch waiting threads ordered by least-recently-checked |
| Order view | `order_id` | Load all threads for one order |
| Gmail dedup | `thread_id` (partial unique, active statuses) | Prevent same Gmail thread linked to two active records simultaneously |
| Timeout scan | `status`, `timeout_at` (sparse) | Phase L3: find threads that have exceeded their deadline |
| Lab grouping | `recipient_email`, `status` | Phase L4: dashboard group-by-laboratory |
| Version unique | `order_id`, `context`, `lab_interaction_version` (partial unique, active statuses) | Prevent two active threads for the same order+context+version. Added Remediation Sprint. |

**Partial unique indexes:** Both `thread_id` and `(order_id, context, lab_interaction_version)` apply only to active statuses (`waiting`, `replied`, `timed_out`, `unreachable`). After unlink or close, the same Gmail thread or the same order+version can be re-linked.

## What Is Not a Collection

| Rejected Collection | Where It Lives Instead | Why |
|--------------------|-----------------------|-----|
| `leads` | Order with status `NEW` | No independent lifecycle |
| `quotes` | `orders.pricing` embedded object | Two fields, never queried alone |
| `lab_requests` | `orders.lab_interactions` embedded array | No meaning outside its order |
| `layouts` | `orders.layouts` embedded array | No meaning outside its order |
| `payments` | `orders.payments` embedded array | No meaning outside its order |
| `events` / `audit_log` | `orders.events` embedded array | Per-order log, never queried cross-order in V1 |
| `users` | Environment config / session | Single-user system in V1 |
| `reminders` | Tasks with type `remind_lab` | Reminders are just a task type |

## Relationships Summary

```
orders (1) ─────────────────────── (1) declarations
   │
   ├── (1) ─────────────────────── (many) tasks
   │
   └── (1) ─────────────────────── (many) lab_comm_threads
```

One Order has one Declaration.
One Order has many Tasks.
One Order has many Lab Comm Threads (one per Gmail monitoring record; typically one or two active at a time).
Tasks, Declarations, and Lab Comm Threads all reference the Order they belong to.

There are no many-to-many relationships in V1.
